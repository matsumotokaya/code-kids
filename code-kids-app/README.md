# コードキッズ（code-kids-app）

子ども向け（6歳・8歳）のプログラミング学習ブラウザゲーム集。
ログイン → ストアでゲームを「ダウンロード」→ 遊ぶ、という流れで、ゲームを1本ずつ増やしていく。

| ゲーム | 状態 |
|---|---|
| ほしあつめ | 遊べる。カードを並べてキャラクターを動かし、おほしさまを集めるパズル。旧アプリ「おえかきロボとさんすうのあそびば」の「おえかきロボット」をゼロベースで作り直したもの |
| ピッタリジャンプ | ストアに「もうすぐ」で表示。旧アプリから移植予定 |
| まほうのアート | ストアに「もうすぐ」で表示。旧アプリから移植予定 |

**本番: https://code-kids-inky.vercel.app/**

## あそびかた

### ログインとストア

1. 最初にパスワードを入れてログインする。パスワードは子ども2人分で、`src/store/session.ts` の `USERS` にある。大文字・小文字は区別しない。本物の認証ではなく「誰の記録を出すか」を決めるだけ
2. ストアでアイコンをタップ →「ダウンロードしますか？」→ 0〜100% のダウンロード演出（約6秒）→「ひらく」で遊べる
3. アイコンを長押しすると「けしますか？」が出て、アプリを消せる。消しても★の記録は残り、入れ直すと続きから遊べる
4. 右上の名前をタップするとログアウトできる。ダウンロード済みのアプリもゲームの記録も、ログインした人ごとに別々

### ほしあつめ

1. タイトルでキャラクター（ロボ / ネコ / ウサギ）を選ぶ。ログインした人ごと・キャラごとに進捗が保存される。左上のボタンでストアに戻る
2. マップでステージを選ぶ（前のステージをクリアすると次が開く）
3. カード（うえ / した / ひだり / みぎ）をタップして並べ、「うごけ！」で実行
4. 「2かい」「3かい」カードは直前のカードに掛かり、そのカード1枚で 2 / 3 マス進む（かけ算・くり返しの導入）
5. いわ・ばんの外にぶつかる、みずに落ちる、ほしが残る、と失敗。カードは消えないので直してもう一度
6. 少ないカード枚数でクリアすると ★3（各ステージの `par` が基準）

## 技術スタック

- Vite 7 / React 19 / TypeScript
- Tailwind CSS v4、motion（アニメーション）、zustand（進捗の localStorage 永続化）
- vite-plugin-pwa（ホーム画面追加・オフライン動作）
- 効果音は Web Audio API で合成（音声ファイルなし）
- タイル・キャラクターはすべてインライン SVG（端末による絵文字の差異を避ける）

## 開発

```bash
npm install
npm run dev        # http://localhost:4649 （同一Wi-Fiのタブレットからは http://<MacのIP>:4649）
npm test           # ゲームエンジンと全ステージの検証（BFS で最短手数 = par を確認）
npm run build      # 型チェック + 本番ビルド → dist/
npm run preview    # dist/ を http://localhost:4650 で配信
```

### ポート番号について

dev が **4649**、preview が **4650**。`vite.config.ts` に固定してある。

Vite はデフォルトが 5173 で、しかも埋まっていると黙って 5174 → 6173 と番号をずらす。
その結果このMacでは複数プロジェクトが 5173 を奪い合い、「localhost:5173 を開いたら別のアプリが出る」
という状態が実際に起きた。そのため独自の番号を決め打ちし、`strictPort: true` で
「埋まっていたらずらさずエラーで止まる」ようにしている。番号を変えるときは `vite.config.ts` の
`DEV_PORT` / `PREVIEW_PORT` を直す。

## 保存しているもの

すべて端末の localStorage。サーバーには何も送らない。

| キー | 中身 |
|---|---|
| `code-kids-session` | ログイン中の人、人ごとのダウンロード済みアプリ |
| `code-kids-progress` | 音のオン/オフ、人ごと・キャラごとのほしあつめの記録 |

`code-kids-progress` はログイン導入前（version 1）はキャラごとの記録だけだった。
version 2 への移行時に、それまでの記録を2人ともに引き継いでいる（`migrateProgress`）。

## タブレット対応

- iPad（縦横）と 10インチ / 7インチの Android タブレット（縦横）で表示を確認している
- 余裕のある画面（幅 720px 以上かつ高さ 700px 以上）では `roomy:` バリアントで要素を大きくする（`src/index.css`）
- ストアとログインは本物のタブレット UI に寄せるため、ゲーム用の丸ゴシックではなく端末のフォント（`font-system`）を使う

## ディレクトリ

```
src/
  apps/        ストアに並ぶアプリ
    catalog.ts   アプリの一覧（名前・説明・遊べるか「もうすぐ」か）
    AppIcon.tsx  アプリアイコンの SVG
    AppRunner.tsx 起動画面を出してからアプリを開く。遊べるアプリの部品はここに登録する
    hoshiatsume/ ほしあつめの入口（タイトル / マップ / プレイの切り替え）
  game/        ほしあつめのロジック（UI非依存・テスト対象）
    types.ts     型
    levels.ts    ステージ定義（座標は x=右, y=下）
    engine.ts    simulate(): プログラムを実行してイベント列を返す
    solver.ts    minCommands(): BFS で最短カード枚数
  store/       session（ログイン・ダウンロード）、progress（人ごと×キャラごとの進捗・サウンド設定）
  audio/       効果音シンセ
  components/  Board（SVGの島）、Character（3キャラのSVG）、tiles、CommandCard、ProgramStrip など
  screens/     Login / Store と、ほしあつめの Title / Map / Play
```

## アプリ（ゲーム）を追加する

1. `src/apps/catalog.ts` の `APPS` に1件足す。まだ作っていないなら `status: 'soon'` にすると、ストアに「もうすぐ」で並ぶ
2. `src/apps/AppIcon.tsx` にアイコンの SVG を足す
3. 遊べるようになったら `src/apps/<id>/` にアプリの入口（`{ user, onQuit }` を受け取る部品）を作り、`AppRunner.tsx` の `COMPONENTS` に登録して `status: 'ready'` にする

ロジックは UI と分けて `npm test` で検証できるようにする（ほしあつめの `src/game` と同じ流儀）。

## ステージを追加する

`src/game/levels.ts` に要素を追加し、`npm test` を実行する。
解けない・`par` が最短と一致しない場合はテストが落ちて正しい値を教えてくれる。

## デプロイ

https://code-kids-inky.vercel.app/ に Vercel で公開済み。`main` への push で自動デプロイされる。

Vercel の **Root Directory は `code-kids-app`**（このディレクトリ）。リポジトリ直下ではない。
残りは Vite プリセットのままでよく、環境変数も不要。
キャッシュ制御は `vercel.json` に置いてある（Service Worker は毎回再検証させる）。

他のホスティングに移す場合も静的サイトなので `dist/` を配信するだけでよい。
ただし PWA はサブパス配信に対応していないので、ルート配信にすること。
